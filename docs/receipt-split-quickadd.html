SplitShare — Quick Receipt Split (least-click)

Two interactive mockups for the #1 job: enter an expense fast and instantly see what everyone's share is — and who owes whom after saving. Both designs collapse the current multi-field form (Forms.jsx) into smart defaults + a single confirmation, and both end with a per-person owe summary. Try Design A's keypad below — shares recompute live per FR-6 (preview-split).

Goal: open → type → done Design A taps: 2 (open + save) Design B taps: 2 (scan + confirm) Everyone preselected by default Live share + owe preview Maps to POST /expenses + preview-split

Design A — “Instant Keypad” (amount-first, zero-navigation)

One screen, no wizard. Amount keypad + split preview are visible simultaneously, so you never navigate to check shares. Members of the active group are preselected (last-used snapshot), payer defaults to You, split defaults to EQUAL. Type digits → watch per-person share update → Save. Tap the keypad and chips — it's live.

Design B — “Scan & Confirm” (receipt-first, 1 glance = done)

For paper receipts: the camera is the entry form. OCR fills title + line items + total, the last-used participants for that group are preselected, and the confirm button carries the full split summary. Optional item-level assignment is tap-person→tap-items — no per-item forms. Images flow through the existing two-phase attach (FR-5).

Recommendation: ship Design A as the default add-expense flow on both web and mobile (it's the least-click path for the most common case — an amount you already know), and keep Design B as the camera entry point that lands in Design A's review layout. Both share the same success screen (A3/B3) so “who owes whom” is always the last thing you see.

API mapping (no backend changes needed): keystroke previews → POST /expenses/preview-split (debounced ~250ms, includes unsettled_preview[] for the FR-8 warning) · save → POST /groups/:id/expenses with Idempotency-Key · owe summary → GET /groups/:id/me + GET /groups/:id/settlement · OCR → client-side or pluggable OCR service, always human-confirm before commit.

A11y: keypad keys are real buttons with aria-label (“digit three”); share list is a live region polite-updating “Chi's share, $3.08”; settlement bar uses aria-expanded per FR-10.
